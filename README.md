# MAX Events

Мини-приложение для мессенджера MAX: афиша событий, волонтерства, туризма и спорта — полный цикл от поиска места до похода с друзьями.

## Разработка (quickstart)

```bash
bun install                  # зависимости монорепо
bun run dev:foundation       # postgres (5443) + redis (6391) в Docker
bun run dev:backend          # NestJS API на :3100 (/api/health/live)
bun run dev:miniapp          # Vite мини-апп на :5173
bun run check                # гейт: test:quality + secrets + format + lint + typecheck + test + grace
```

Структура: `apps/app-miniapp` (React/Vite, MAX Bridge), `apps/svc-backend` (NestJS + TypeORM), `packages/api-contracts` (zod-контракты API).

## Идея

Главный объект продукта — не событие, а **план**: не «вот концерт», а «вот куда вы можете пойти вместе». Вокруг плана естественно складывается весь цикл: друзья, чат, приглашение, голосование, билет, маршрут, напоминание и фотографии после события.

Так MAX Events перестает быть обычной афишей и становится **персональным досуговым ассистентом и органайзером совместного досуга**, глубоко встроенным в социальный граф мессенджера. Это сложно скопировать стороннему сервису без доступа к друзьям и чатам MAX.

## Аудитория

- **Пользователи** — люди, которые ищут, куда сходить: одному, с друзьями или с новыми знакомыми (концерты, выставки, походы, спорт, волонтерские акции).
- **Организаторы и площадки** — частные места, развлекательные площадки и организаторы событий, которым нужны инструменты публикации, продаж и продвижения.

## Функциональность

### Поиск мест и мероприятий

- Список и интерактивная карта: постоянные места (парки, беседки, локации) и события на конкретную дату.
- Категории: афиша/события, волонтерство, туризм, спорт.
- Фильтры по дате, категории, рейтингу, интересам и городу.
- Запись на событие внутри приложения; для платных мероприятий — переход по ссылке на официальную страницу оплаты организатора.
- **Waitlist**: если места заняты — «Встать в лист ожидания»; при освобождении места — уведомление с таймером подтверждения.

### «Куда пойдём?» — сценарий для тех, кто не знает, чего хочет

- Одна из главных кнопок на главном экране вместо классического поиска по фильтрам.
- Быстрый выбор контекста: Я один / С друзьями / С девушкой / С детьми → Активное / Спокойное / Необычное / Бесплатное / До 3000 ₽ → 5 конкретных вариантов.
- Кнопка «Отправить друзьям» — результат сразу уходит в чат.

### «Что делать сегодня?» — персональная подборка

- Готовая подборка вместо поиска по каталогу: «12 событий рядом, 3 подходят тебе, на 2 идут друзья».
- Карточки с контекстом: «10 минут от тебя», «Идет Анна», «Свободный вход», «Осталось 12 мест».

### «Рядом со мной» и свободное время

- Спонтанный сценарий: что происходит рядом прямо сейчас.
- Временная шкала: **Сейчас → через час → вечером → завтра**.
- Режим «У тебя свободно 3 часа»: MAX собирает готовые варианты досуга — «расслабиться» (парк → выставка → бар), «активно» (скалодром → концерт), «с друзьями» (Анна и Дима свободны → матч через 50 минут).

### «С кем пойти?» — умный сборщик компании

- **Статусы на событии**: Хочу пойти / Скорее всего пойду / Иду / Ищу компанию / Ищу попутчика / Ищу, с кем продолжить после события. Статусы питают matchmaking: «На концерт идут 24 человека, 7 твоих знакомых, 4 ищут компанию, 2 едут из твоего района».
- **«Собрать компанию»** — полноценный механизм: выбрать событие и друзей → MAX показывает, кто свободен → предлагает время встречи → автоматически создает чат → собирает подтверждения → напоминает не ответившим («Ты + 2 из 5: Дима подтвердил, Катя смотрит, Андрей занят»).
- **Знакомства через события**: режим «Хочу найти людей с похожими интересами» — пользователь выбирает интересы (электронная музыка, походы, спорт, выставки) и видит: «23 человека рядом с похожими интересами, 3 ищут компанию сегодня». Матч происходит естественно — «вы оба хотите на этот концерт», без механики дейтинг-приложений.

### Совместные планы

- Полноценный объект «Поход»: кто идет, где и во сколько встречаемся, кто покупал билеты, общий чат, маршрут, напоминания.
- Пример карточки: «The Weekend Tribute. Ты + 3 друга. Сбор 18:20 у метро. 850 м от тебя».
- **Автоплан после выбора события**: пользователь нажимает «Пойду» → MAX предлагает «Собрать план»: до события 2 ч 40 мин, 32 мин до места, рядом 4 места поесть, Дима уже идет → «17:30 ужин → 18:40 дорога → 19:20 встреча → 20:00 концерт».
- **Общий бюджет плана**: билет 850 ₽ + такси 620 ₽ + ужин ~1 200 ₽ → «Итого ~2 670 ₽/человек»; фиксация кто что оплатил и кто кому должен.
- **Повторяющиеся планы**: «каждый четверг падел», «первая суббота месяца — поход» — MAX автоматически создает будущие планы и опрашивает участников.

### Режим «Мы» — временные группы

- Отдельная сущность поверх профиля: «Мы → Поездка в Казань» — 4 участника, события, места, чат, билеты, маршрут, бюджет, фотографии.
- Мини-группа внутри MAX; после поездки объект сохраняется как общая история.

### События друзей и reverse discovery

- Экран «Твои люди идут»: Анна → выставка, Дима → матч, Катя → фестиваль. CTA «Присоединиться» — главный драйвер возвращаемости.
- Reverse discovery: «Твои люди открыли 14 новых мест», «Анна недавно была в 6 местах, где ты не был → посмотреть её маршрут» (с настройками приватности).

### Совместный выбор в чате

- В чат MAX отправляется голосование «Куда идем в пятницу?» с вариантами событий.
- Друзья голосуют, приложение показывает лучший вариант — инструмент принятия решения, а не каталог.

### Микро-события (UGC)

- Пользователь создает маленький план за 30 секунд: «Играем в баскетбол сегодня в 19:00 — сейчас 3/6 человек», «Идем гулять в лес в 14:00 — +2 места».
- Не только крупные организованные мероприятия — потенциально сильный механизм пользовательского контента.

### Место как социальный объект

- Страница места (например, ВДНХ): события сегодня, друзья («Анна была здесь 3 раза», «Дима идет сегодня»), оценки людей (атмосфера 4.8, цены 3.9), популярность («482 человека были сегодня»), личная история («Ты был здесь 6 раз, 2 новых знакомства»).
- Связывает места + события + людей + историю.

### Социальный proof вместо абстрактных рейтингов

- Вместо «4.7/5»: «Анна рекомендует», «Дима был», «8 твоих знакомых сохраняли», «24 человека собираются».
- Блок «Твои люди» — один из самых ценных на главном экране.

### Социальный слой

- Лента и истории: фото и впечатления с мест и мероприятий, лайки, комментарии, «стена» места/события.
- Синхронизация друзей из мессенджера, приглашения на события.
- **Совместные коллекции**: не только личные списки — «Саша + Кирилл: хотим сходить / уже были / идеи на выходные», шаринг коллекции в чат.
- **Check-in «Я здесь»**: основа статистики, достижений, рейтингов и соцпубликаций.

### «После события» — retention loop

- После посещения: «Как прошло?» — быстрая оценка (звезды + атмосфера/организация/цена/место/«пошел бы еще раз») и фото.
- Посещение превращается в данные: «Ты был на 8 концертах за год, тебе особенно нравятся камерные площадки», «3 твоих друга были здесь — средняя оценка 4.8».
- **«После меня» / taste graph**: рекомендации по последовательности посещений — «После 3 джаз-концертов тебе неожиданно зашли камерные выступления».

### Чаты мероприятий

- При создании события в MAX автоматически создается чат; записавшиеся вступают, знакомятся, договариваются пойти вместе.

### Календарь и smart alerts

- Личный календарь: запланированные и прошедшие события, синхронизация с внешними календарями.
- Видимость планов для друзей («я иду на это событие»).
- **Smart alerts вместо обычных напоминаний** — уведомление как действие, а не шум: «Концерт через 1 ч 40 мин. Дима уже вышел. До места 28 минут. Если выйти сейчас — будешь за 20 минут до начала», «Похоже, будет дождь. Встречаемся не у входа, а внутри?».
- Напоминания о событиях из списков: «В субботу рядом будет 4 события из твоего списка».

### Списки и подборки

- Хочу сходить, Избранное, На выходные, С детьми, С друзьями, Попробовать потом.

### Профиль, «Мой город», достижения

- Мини-профиль со статистикой посещений, интересы пользователя, настройки (город, приватность, напоминания, рекомендации).
- **«Мой город»** — личная история: 38 мест, 12 событий, 5 новых районов; карта превращается в личную карту впечатлений.
- Достижения и «штампы» с осмысленными целями: «Исследователь города» (10 новых мест), «Музыкальный фанат» (5 концертов), «Город за выходные» (3 района), «Волонтер» (5 акций). Коллекционирование мест.

### Маршрут на день

- Сборка нескольких событий в единый план: «12:00 выставка → 15 мин → 15:30 кафе → 20 мин → 18:00 концерт» — с автоматическим маршрутом.
- **Оптимизация маршрута**: «Сейчас 11.4 км → после оптимизации 6.8 км, экономия 47 минут» — особенно сильно для туристического сценария.

### Подписки

- На организации и площадки (новости и события от них).
- На интересы: «электронная музыка», «походы рядом» — новые события приходят автоматически.

### Геосоциальный слой

- На карте видно «Здесь были твои друзья»: Анна была здесь, Дима часто ходит сюда — социальное доказательство при выборе места.

### AI-помощник

- Не отдельный чат, а часть интерфейса: запрос естественным языком — «Хочу вечером куда-нибудь, максимум 3000 ₽, с девушкой, желательно музыка» → «Нашел 7 вариантов, 2 по твоей истории, 1 уже сохранила твоя девушка».
- «Сделай нам план на субботу» — собирает день целиком из мероприятий.

### Панель организатора

- Создание и управление событиями и местами на карте, статистика (просмотры, записи, продажи).
- Промо-инструменты: промокоды, ранний доступ, акции «приведи друга», спецпредложения, таргетированные подборки («покажи концерт тем, кто посещал 3+ концерта за полгода»), платное продвижение.
- **Рейтинг организатора**: 4.8 ⭐, «97% участников рекомендуют», 6 400 посещений, среднее время ответа, «93% мероприятий начинаются вовремя» — полезнее обычного рейтинга.

### Аутентификация

- Быстрый вход через платформу MAX, стандартная регистрация как альтернатива.

## Приоритеты

- **P0 — ядро**: события + карта + запись + чат + календарь + друзья.
- **P1 — главное отличие от афиши**: «С кем пойти» (статусы, сборщик компании) + события друзей + совместные планы + «что делать сегодня» + «Куда пойдём?».
- **P2 — удержание**: избранное/списки + подписки + check-in + достижения + «Мой город» + «После события» (отзывы, taste graph) + микро-события + waitlist.
- **P3 — интеллектуальный слой**: AI-рекомендации + персональные маршруты + планирование дня + автоплан после выбора события + оптимизация маршрута + smart alerts.
- **P4 — экосистема**: организаторы + промо-инструменты + рейтинг организаторов + аналитика + монетизация. Режим «Мы» и общий бюджет — с ростом совместных планов (P1→P2).

## MVP (первый этап)

1. Каталог событий и мест: список + карта, фильтры по дате/категории/городу.
2. Страница мероприятия: запись/бронь + ссылка на оплату на сайте организатора для платных событий.
3. Авточат мероприятия в MAX + вступление по записи.
4. Вход через MAX, базовый профиль, личный календарь, напоминания ботом.

Кандидаты на быстрое расширение MVP (P1): «С кем пойти» со статусами и экран «События друзей» — они дешевле всего показывают уникальность продукта на социальном графе MAX.

## Ценность

- **Пользователю** — один сервис вместо афиши, карт, чатов «с кем пойти» и календаря; открытие событий через друзей; поход как готовый план, а не самостоятельная организация.
- **Мессенджеру** — вовлекающий mini app, естественно использующий социальный граф, чаты и ботов.
- **Организаторам** — канал продаж и продвижения с прямым доступом к аудитории MAX и таргетингом по интересам.

## Принятые решения

### Дизайн мини-аппа

Вёрстка и UX-паттерны — в стилистике Instagram (карточная лента, крупные медиа, истории-подобные элементы), цветовая схема — мессенджера MAX. Палитра берётся из официальной дизайн-системы `@maxhub/max-ui` (CSS-переменные, fallback = light-схема): MAX Bridge не отдаёт параметры темы (проверено по https://dev.max.ru/docs/webapps/bridge), поэтому тёмная тема заблокирована API платформы. Разделение ответственности: backend развивает отдельная команда; фронтенд строится на zod-контрактах `@max-events/api-contracts` + mock-слое до готовности API.

### Платежи

На старте встроенной оплаты нет — принципиально. Запись/бронь внутри мини-апа; если мероприятие платное, пользователь переходит по ссылке на официальный сайт/страницу оплаты организатора и платит там. Встроенные платежи — возможный следующий этап.

### Модерация

Пост-модерация + жалобы. События, места и контент ленты публикуются сразу; проверка — по жалобам пользователей (кнопка «пожаловаться») и выборочно. Санкции — снятие публикации и бан организатора.

### Источник событий на старте

Ручное наполнение: команда сама добавляет стартовый пул реальных событий и мест (целевой город). Парсинг/агрегация афиш не используем. Дополнительно — привлекаем первых партнеров-организаторов, которые заводят события сами через панель организатора. Микро-события пользователей — второй источник UGC-контента.

### Монетизация

Две линии дохода:

1. Комиссия с продажи билетов — основная модель, активируется с появлением встроенных платежей.
2. Платное продвижение для организаторов — поднятие события в выдаче, баннеры, пины на карте, таргетированные подборки (доступно уже на старте).
