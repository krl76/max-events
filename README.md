# MAX Events

Мини-приложение и чат-бот для мессенджера MAX: афиша событий, запись, планы с друзьями и подборки «что делать сегодня».

Основной пользовательский сценарий проверяется в MAX. Docker поднимает ту же мини-аппу и API локально для разбора стека.

| Что | Где |
| --- | --- |
| Чат-бот | [t691_hakaton_max_bot](https://max.ru/t691_hakaton_max_bot) |
| Мини-приложение | кнопка «Открыть афишу» в боте; хост `https://events.versacegus.cc` |

## Назначение решения

MAX Events — персональный досуговый ассистент внутри MAX. Пользователь ищет, куда сходить (афиша, волонтёрство, туризм, спорт), записывается на событие, собирает компанию и держит поход как план: место, время, участники, напоминание.

Организаторам — кабинет публикации событий и мест, записи, промо.

## Основной пользовательский сценарий

1. Открыть бота `t691_hakaton_max_bot` в MAX, написать «Начать».
2. Получить приветствие с фото и кнопки меню.
3. Нажать «Что сегодня» или «Куда пойти» (компания → настроение → бюджет) либо написать «джаз вечером до 3000».
4. Записаться на событие из чата или открыть мини-приложение кнопкой «Открыть афишу».
5. В мини-приложении пройти онбординг (город), открыть карточку события, записаться, увидеть запись в «Мои брони» / календаре.

Локальный Docker повторяет мини-приложение и API в браузере (вход без клиента MAX). Чат-бот и вход через MAX проверяются только в мессенджере.

## Состав и архитектура решения

Монорепозиторий:

| Часть | Путь | Роль |
| --- | --- | --- |
| Мини-приложение | `apps/app-miniapp` | React / Vite / Ionic, MAX Bridge |
| Backend API | `apps/svc-backend` | NestJS, TypeORM, чат-бот |
| Контракты | `packages/api-contracts` | Zod-схемы API |
| Локальный стек | `docker-compose.yml` | Postgres, Redis, API, nginx с мини-приложением |

```
MAX (клиент)
  ├─ Bot API  ──webhook──►  backend :3100  ──►  postgres
  └─ Mini App ──HTTPS────►  nginx (статика + /api) ──►  backend
                                                      ──►  redis
backend по сети ──►  KudaGo, Open-Meteo, Wikidata, OpenCode Zen (по желанию)
```

Аутентификация пользователя: HMAC `initData` мини-приложения MAX. Панель организатора: login/password, сессия в Redis. Каталог: сид + импорт KudaGo + события организаторов и пользователей.

## Одна команда запуска (Docker)

Из корня репозитория, Docker Engine с Compose v2:

```bash
docker compose up --build
```

Поднимаются Postgres, Redis, API и мини-приложение. Миграции и стартовый каталог выполняются при старте backend.

- Мини-приложение: http://localhost:8080
- API health: http://localhost:3100/api/health/live → `{"status":"ok"}`

Первая сборка занимает несколько минут. Повторный запуск без пересборки: `docker compose up`.

## Необходимые параметры окружения

Для **основного сценария в MAX** нужен клиент MAX и доступ к боту `t691_hakaton_max_bot`. Платформу MAX внутри Docker воспроизвести нельзя — условия проверки ниже, в разделе про внешние сервисы.

Для **локального Docker** достаточно Docker. Файл `.env` не обязателен: compose подставляет значения по умолчанию (`MAX_BOT_TOKEN=local-dev-token`, вход через `AUTH_ALLOW_BROWSER`).

Для **своего** локального токена MAX или пароля организатора создайте `.env` в корне (см. `.env.example`) — Compose его подхватит для `MAX_BOT_TOKEN`, `ORGANIZER_LOGIN`, `ORGANIZER_PASSWORD`.

## Переменные окружения

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | да (в контейнере задана) | Postgres, `postgres://…` |
| `REDIS_URL` | да (в контейнере задана) | Redis, `redis://…` |
| `PORT` | нет, по умолчанию `3100` | Порт API |
| `NODE_ENV` | нет, в Docker local: `development` | `production` на проде; без значения считается production |
| `MAX_BOT_TOKEN` | для MAX и подписи initData | Токен бота MAX. Локально: `local-dev-token` |
| `AUTH_ALLOW_BROWSER` | нет | `true` только локально/стенд: `POST /api/auth/browser-initdata`. На `events.versacegus.cc` выключено |
| `BOT_WEBHOOK_SECRET` | нет | Секрет вебхука. На проде считается из токена |
| `BOT_PUBLIC_URL` | нет | Публичный origin картинок и вебхука |
| `BOT_LONGPOLL` | нет | `true` — long poll вместо вебхука (только dev) |
| `MAX_APP_URL` | нет | `https://max.ru/t691_hakaton_max_bot` |
| `ORGANIZER_LOGIN` / `ORGANIZER_PASSWORD` | для кабинета | Первый вход создаёт/захватывает аккаунт. Локально: `max-events` / `demo-password-12` |
| `MODERATOR_MAX_USER_IDS` | нет | MAX user id модераторов, через запятую |
| `PAYMENT_PROVIDER` | нет | `sandbox` или `none`. Деньги за билет — по ссылке организатора |
| `PAYMENT_SECRET` | для webhook sandbox | HMAC вебхука оплаты |
| `FRIENDS_DEMO_ALL_USERS` | нет | В `development`/`test` все пользователи — друзья. На проде игнорируется |
| `MODEL_API_KEY` | нет | Ключ OpenCode Zen. Без ключа — встроенный keyword-парсер |
| `MODEL_API_URL` / `MODEL_API_MODELS` | нет | Хост и список моделей ассистента |
| `STORAGE_DIR` | нет | Каталог загруженных фото |
| `POSTGRES_PASSWORD` | на проде | Пароль Postgres в `docker-compose.prod.yml` |

## Зависимости

- Docker Engine и Compose v2 — запуск всего локального стека.
- Образы: `postgres:16-alpine`, `redis:7-alpine`, `nginx:1.27-alpine`, `oven/bun:1.3.14-debian`.
- Языки и пакеты зафиксированы в `bun.lock` (`packageManager`: `bun@1.3.14`). Backend: NestJS 11, TypeORM, pg, ioredis, zod. Мини-приложение: React 19, Vite, Ionic, MapLibre, Leaflet.
- Клиент MAX — для основного сценария (бот и мини-приложение внутри мессенджера).

## Внешние сервисы и интеграции

### MAX (нужен для основного сценария, в Docker нет)

Назначение: идентификация пользователя (`initData`), чат-бот, кнопка `open_app` в мини-приложение, доставка вебхуков и исходящих сообщений.

Условия проверки:

1. Установлен MAX.
2. Открыт бот [t691_hakaton_max_bot](https://max.ru/t691_hakaton_max_bot).
3. Прод `https://events.versacegus.cc` доступен из сети MAX (вебхук `POST /api/bot/webhook`).

Локальный Docker открывает мини-приложение в браузере (`AUTH_ALLOW_BROWSER`), без клиента MAX.

### Остальные интеграции (стек поднимается и без них)

| Сервис | Зачем | Если недоступен |
| --- | --- | --- |
| KudaGo public API | Дополнительная афиша Москвы и СПб | Каталог из сида и кабинета организатора |
| Open-Meteo | Погода на карточке события и карте | Поле погоды пустое |
| Wikidata SPARQL | Кандидаты для городских прогулок | Прогулка без внешних точек |
| OpenStreetMap / OpenMapTiles | Подложка карты; локально nginx проксирует `/tiles` с прода | Карта без «своей» подложки, остаётся OSM raster |
| picsum.photos | Заглушки фото в webview MAX | Пустые превью |
| OpenCode Zen | NL-парсер ассистента | Keyword-парсер на русском |

Исходящие вызовы к `platform-api2.max.ru` идут с сертификатами НУЦ Минцифры, они вшиты в образ backend.

## Описание работы с данными

- **Postgres** — пользователи (MAX id, имя, username, фото), профили и настройки приватности, места и события, брони, планы, записи, лента, отзывы, жалобы, организации (пароль — scrypt).
- **Redis** — сессии кабинета организатора, кэш прогноза погоды.
- **Файлы** — загруженные изображения в `STORAGE_DIR` / volume `uploads`.
- **Вход** — сервер проверяет подпись `initData` ключом бота. Без валидного initData API отвечает 401. Каталог и брони — от имени текущего пользователя; чужие брони и планы закрыты.
- **Геолокация** — браузер/webview, на сервере не хранится как обязательное поле; координаты уходят в запросы «рядом» и маршрутов.
- **Секреты** — только в окружении, не в git. `.env` в `.gitignore`.

## Порядок работы с тестовыми данными

Локальный `docker compose up --build` сам прогоняет миграции и `seed-cli`:

- город Москва, места (Парк Горького, Третьяковка, ВДНХ, Лужники и др.);
- события всех четырёх категорий, в том числе «Джаз в Парке Горького», «Субботник на ВДНХ»;
- организация `max-events` / пароль `demo-password-12`.

Пользователь в браузере: кнопка «Войти» на http://localhost:8080 запрашивает `POST /api/auth/browser-initdata` и получает подписанный initData учётки owner.

Повторный seed идемпотентен (upsert по ключам каталога). Сброс данных:

```bash
docker compose down -v
docker compose up --build
```

На проде каталог уже заполнен (сид + KudaGo). Отдельный тестовый пароль организатора в README не публикуется.

- «Начать» в боте: сообщение «Привет, …», фото, кнопка «Открыть афишу в приложении», пункты «Что сегодня» / «Куда пойти».

## Известные ограничения

- Список друзей MAX платформа мини-приложениям не отдаёт; социальный граф на проде пустой, пока нет API друзей. В локальном Docker включён демо-режим «все пользователи — друзья».
- Встроенной оплаты нет: платное событие ведёт на `paymentUrl` организатора. `PAYMENT_PROVIDER=sandbox` только для отладки.
- Вебхук бота и вход через MAX работают на проде `events.versacegus.cc`. Локальный стек — браузерный вход.
- Карта «Своя» читает PMTiles с прода (`/tiles`). Без сети до `events.versacegus.cc` эта подложка в локальном Docker пустая.
- Импорт KudaGo и погода зависят от внешних HTTP API.
- `AUTH_ALLOW_BROWSER` и `FRIENDS_DEMO_ALL_USERS` на боевом MAX-хосте выключены.

## Остановка и повторный запуск

Остановить, сохранив базу и загрузки:

```bash
docker compose down
```

Запустить снова (без пересборки образов):

```bash
docker compose up
```

Пересобрать образы после изменения кода:

```bash
docker compose up --build
```

Полностью стереть тома (каталог, брони, загрузки) и поднять заново:

```bash
docker compose down -v
docker compose up --build
```

Логи: `docker compose logs -f backend miniapp`.
